# Contributing

Thanks for your interest in contributing! Contributions such as bug fixes, features, documentation, and tests are welcome.

## Getting Started

1. Check existing issues and pull requests before starting.
2. For larger changes, open an issue to discuss your idea first.
3. Fork the repository and create a branch for your changes:

```bash
git checkout -b feature/your-change
```

## Making Changes

* Follow the project's existing coding style and structure.
* Keep changes focused and avoid unrelated modifications.
* Add or update tests when appropriate.
* Update documentation when needed.
* Run tests, linting, and formatting checks before submitting.

## Commits

Use clear, descriptive commit messages, for example:

```text
feat: Add user authentication
fix: Handle invalid input
docs: Update installation guide
```

## Pull Requests

Before opening a PR:

* [ ] Tests pass
* [ ] Code is formatted and linted
* [ ] Documentation is updated if needed
* [ ] The PR clearly explains what changed and why

Keep pull requests focused and easy to review.

## Issues

When reporting a bug, include:

* What happened
* Steps to reproduce it
* Expected vs. actual behavior
* Relevant logs or error messages

For security vulnerabilities, please use the project's private security reporting process rather than opening a public issue.
